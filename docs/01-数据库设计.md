# 数据库设计

## 总体约定

- 库名 `harmony`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`，引擎 InnoDB。
- 主键 `id BIGINT UNSIGNED AUTO_INCREMENT`。
- 时间字段 `created_at`、`updated_at` 用 `DATETIME(3)`，由 GORM 维护；接口输出时转成 `int64` 毫秒。
- 金额字段 `BIGINT NOT NULL DEFAULT 0`，单位分，用 `CHECK` 约束保证非负。
- 枚举用短字符串（`VARCHAR(16)`）而不是数字，查库时可以直接读懂；取值在 `infra/consts` 中定义常量。
- 不使用物理外键，关联完整性在 service 层事务内校验，避免迁移和合并时的锁冲突。
- 不做软删除。`fen.md` 要求有关联时禁止删除，能删除的数据都是没有引用的。
- 所有表带 `owner_id BIGINT UNSIGNED NOT NULL`，所有查询都必须带上它。

## 实体关系

```text
person 1 ─── N record N ─── 1 event
                 │ N
                 │
                 1
               book ──(merged_into_id)──> book

record(送) N ─── record_repay ─── N record(收)

recognize_task 1 ─── N record（source=recognize）
```

## 枚举取值

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `person.relation` | `relative` `friend` `colleague` `neighbor` `other` | 亲戚 朋友 同事 邻居 其他 |
| `book.status` | `normal` `merged` | 正常 已合并 |
| `event.type` | `wedding` `funeral` `fullmoon` `housewarming` `school` `newyear` `other` | 红事 白事 满月 乔迁 升学 过年 其他 |
| `event.host` | `self` `other` | 自家办 别人家办 |
| `record.direction` | `in` `out` | 收 送 |
| `record.status` | `pending` `repaid` `none` | 待还 已还 无需还 |
| `record.source` | `manual` `recognize` `import` | 手动 识别 导入 |
| `record.date_precision` | `day` `month` `year` | 日期精确到日、月、年 |

本子类别和记录名目允许用户自定义，所以不写死成枚举，统一存放在 `dict_item` 表中。

## 表结构

### app_user

第一阶段只有一条种子数据 `id=1`；第二阶段接入微信登录后，由 openid 生成新用户。

```sql
CREATE TABLE app_user (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  openid      VARCHAR(64)  NULL,
  unionid     VARCHAR(64)  NULL,
  nickname    VARCHAR(64)  NOT NULL DEFAULT '',
  created_at  DATETIME(3)  NOT NULL,
  updated_at  DATETIME(3)  NOT NULL,
  UNIQUE KEY uk_openid (openid)
);
INSERT INTO app_user (id, nickname, created_at, updated_at) VALUES (1, '本机用户', NOW(3), NOW(3));
```

### dict_item

存放本子类别（`book_category`）和记录名目（`item_kind`）。内置项 `builtin=1` 不可删除。

```sql
CREATE TABLE dict_item (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id    BIGINT UNSIGNED NOT NULL,
  dict_type   VARCHAR(32)  NOT NULL,
  code        VARCHAR(32)  NOT NULL,
  label       VARCHAR(32)  NOT NULL,
  color       VARCHAR(16)  NOT NULL DEFAULT '',
  sort        INT          NOT NULL DEFAULT 0,
  builtin     TINYINT(1)   NOT NULL DEFAULT 0,
  created_at  DATETIME(3)  NOT NULL,
  updated_at  DATETIME(3)  NOT NULL,
  UNIQUE KEY uk_owner_type_code (owner_id, dict_type, code)
);
```

内置数据：

| dict_type | code | label | color |
| --- | --- | --- | --- |
| `book_category` | `renqing` | 人情礼 | `cinnabar` |
| `book_category` | `huopao` | 火炮 | `amber` |
| `book_category` | `other` | 其他 | `stone` |
| `item_kind` | `cash` | 现金 | `cinnabar` |
| `item_kind` | `huopao` | 火炮 | `amber` |
| `item_kind` | `gift` | 实物礼品 | `teal` |

用户自定义项的 code 用 `c_` 加短随机串，label 由用户填写。`color` 是前端色板里的颜色名，不是色值，取值见 `03-前端交互与UI规范.md`。

### person

```sql
CREATE TABLE person (
  id            BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id      BIGINT UNSIGNED NOT NULL,
  name          VARCHAR(32)  NOT NULL,
  name_pinyin   VARCHAR(128) NOT NULL DEFAULT '',
  name_initials VARCHAR(32)  NOT NULL DEFAULT '',
  relation      VARCHAR(16)  NOT NULL DEFAULT 'other',
  phone         VARCHAR(32)  NOT NULL DEFAULT '',
  remark        VARCHAR(255) NOT NULL DEFAULT '',
  created_at    DATETIME(3)  NOT NULL,
  updated_at    DATETIME(3)  NOT NULL,
  KEY idx_owner_name (owner_id, name),
  KEY idx_owner_initials (owner_id, name_initials)
);
```

- 姓名不加唯一约束：现实中确实有同名的不同人，`fen.md` 要求的是"提示后可继续新建"。
- `name_pinyin` 存全拼（`zhangsan`），`name_initials` 存首字母（`zs`）。两者都在写入和改名时由后端生成，前端不传。

### book

```sql
CREATE TABLE book (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id        BIGINT UNSIGNED NOT NULL,
  name            VARCHAR(64)  NOT NULL,
  category        VARCHAR(32)  NOT NULL DEFAULT 'renqing',
  default_event_id BIGINT UNSIGNED NULL,
  description     VARCHAR(255) NOT NULL DEFAULT '',
  status          VARCHAR(16)  NOT NULL DEFAULT 'normal',
  merged_into_id  BIGINT UNSIGNED NULL,
  merged_at       DATETIME(3)  NULL,
  created_at      DATETIME(3)  NOT NULL,
  updated_at      DATETIME(3)  NOT NULL,
  KEY idx_owner_status (owner_id, status)
);
```

`category` 引用 `dict_item(book_category).code`。`default_event_id` 是礼簿的默认事项：一本纸质礼簿通常对应一场事，设置后在这本礼簿上记账、连续录入、识别录入时自动带出。

### event

```sql
CREATE TABLE event (
  id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id    BIGINT UNSIGNED NOT NULL,
  name        VARCHAR(64)  NOT NULL,
  type        VARCHAR(16)  NOT NULL DEFAULT 'other',
  event_date  DATE         NULL,
  location    VARCHAR(128) NOT NULL DEFAULT '',
  host        VARCHAR(16)  NOT NULL DEFAULT 'other',
  host_person_id BIGINT UNSIGNED NULL,
  date_precision VARCHAR(8) NOT NULL DEFAULT 'day',
  placeholder TINYINT(1)   NOT NULL DEFAULT 0,
  remark      VARCHAR(255) NOT NULL DEFAULT '',
  created_at  DATETIME(3)  NOT NULL,
  updated_at  DATETIME(3)  NOT NULL,
  KEY idx_owner_date (owner_id, event_date),
  KEY idx_owner_host_person (owner_id, host_person_id)
);
```

- `host_person_id`：别人家办的事项，记下是谁家办的。纸本还礼标注里的"孙女结婚""生日"都是某个人家的事，补录时按"这个人加事项名"查找已有事项，避免同一件事被重复新建。
- `date_precision`：含义与 record 表相同。
- `placeholder`：系统占位事项"纸本未注明事项"，每个 owner 只有一个，在种子数据里创建。标注没有写对方事项时，还礼记录归到这里。事项列表默认不显示占位事项，统计里单独列为一行。

### record

系统的核心表。

```sql
CREATE TABLE record (
  id                 BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id           BIGINT UNSIGNED NOT NULL,
  person_id          BIGINT UNSIGNED NOT NULL,
  event_id           BIGINT UNSIGNED NOT NULL,
  book_id            BIGINT UNSIGNED NOT NULL,
  origin_book_id     BIGINT UNSIGNED NOT NULL,
  item_kind          VARCHAR(32)  NOT NULL,
  direction          VARCHAR(8)   NOT NULL,
  amount_cent        BIGINT       NOT NULL DEFAULT 0,
  gift_name          VARCHAR(64)  NOT NULL DEFAULT '',
  gift_value_cent    BIGINT       NOT NULL DEFAULT 0,
  total_cent         BIGINT AS (amount_cent + gift_value_cent) STORED,
  occurred_on        DATE         NOT NULL,
  date_precision     VARCHAR(8)   NOT NULL DEFAULT 'day',
  status             VARCHAR(16)  NOT NULL,
  remark             VARCHAR(255) NOT NULL DEFAULT '',
  paper_note         VARCHAR(255) NOT NULL DEFAULT '',
  paper_page         VARCHAR(16)  NOT NULL DEFAULT '',
  paper_seq          INT          NOT NULL DEFAULT 0,
  source             VARCHAR(16)  NOT NULL DEFAULT 'manual',
  recognize_task_id  BIGINT UNSIGNED NULL,
  created_at         DATETIME(3)  NOT NULL,
  updated_at         DATETIME(3)  NOT NULL,
  CONSTRAINT ck_amount_nonneg CHECK (amount_cent >= 0 AND gift_value_cent >= 0),
  CONSTRAINT ck_amount_or_gift CHECK (amount_cent > 0 OR gift_name <> ''),
  KEY idx_owner_person_date (owner_id, person_id, occurred_on),
  KEY idx_owner_event (owner_id, event_id),
  KEY idx_owner_book (owner_id, book_id),
  KEY idx_owner_dir_status (owner_id, direction, status, occurred_on),
  KEY idx_owner_date (owner_id, occurred_on),
  KEY idx_dup (owner_id, person_id, event_id, book_id, item_kind),
  KEY idx_owner_book_page (owner_id, book_id, paper_page, paper_seq)
);
```

字段说明：

- `origin_book_id`：创建记录时等于 `book_id`，之后永不修改。合并本子只改 `book_id`，追溯时看这个字段。
- `item_kind`：引用 `dict_item(item_kind).code`。合并本子不改这个字段，所以跨类别合并后按名目统计仍然准确。
- `total_cent`：MySQL 存储型生成列，等于现金加礼品估价。所有统计只对这一列求和，从结构上杜绝金额与估价被重复计入。
- `status`：表示"这笔是否还在等回礼"，收和送两个方向都使用。收方向的待还表示"我欠别人"，送方向的待还表示"别人欠我"。作为还礼的那笔"送"记录，创建时状态固定为 `none`。
- `ck_amount_or_gift` 是数据库层的兜底约束，service 层会先校验并返回友好提示。
- `date_precision`：取值 `day`、`month`、`year`。纸本标注常常只写到"11年国庆""11年正月"，这时按该月或该年第一天存储，精度记为 month 或 year，界面按精度显示。排序和按年统计直接使用 `occurred_on`，不受影响。
- `paper_note`：纸本上这一行旁边的手写标注原文，照抄保存。它是还礼记录的来源依据，也能被搜索到。
- `paper_page`、`paper_seq`：纸本页码（如"1-10"）和本页第几行，用来从系统回查纸本。两个字段都可以不填。

### paper_page_check

按页核对。录入或识别一页纸本时，记下纸本上写的本页合计，用来和实际录入的金额比对。

```sql
CREATE TABLE paper_page_check (
  id               BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id         BIGINT UNSIGNED NOT NULL,
  book_id          BIGINT UNSIGNED NOT NULL,
  paper_page       VARCHAR(16)  NOT NULL,
  declared_cent    BIGINT       NOT NULL,
  created_at       DATETIME(3)  NOT NULL,
  updated_at       DATETIME(3)  NOT NULL,
  UNIQUE KEY uk_book_page (owner_id, book_id, paper_page)
);
```

实际录入合计不存，而是实时计算：`SUM(total_cent) WHERE book_id=? AND paper_page=? AND direction='in'`。只统计收方向，因为纸本页合计只包括来客给的礼，不包括还礼。合并本子时，把源本子的核对记录一并迁移到目标本子。

### record_repay

还礼关联，多对多：一次还礼可以关联多笔收礼，一笔收礼也可以分多次还。

```sql
CREATE TABLE record_repay (
  id                BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id          BIGINT UNSIGNED NOT NULL,
  repay_record_id   BIGINT UNSIGNED NOT NULL,
  origin_record_id  BIGINT UNSIGNED NOT NULL,
  created_at        DATETIME(3) NOT NULL,
  UNIQUE KEY uk_pair (repay_record_id, origin_record_id),
  KEY idx_origin (origin_record_id)
);
```

约束都在 service 层校验：`repay_record_id` 必须是送方向的记录，`origin_record_id` 必须是收方向的记录，两者必须属于同一个人。

### book_merge_log

```sql
CREATE TABLE book_merge_log (
  id              BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id        BIGINT UNSIGNED NOT NULL,
  target_book_id  BIGINT UNSIGNED NOT NULL,
  source_books    JSON          NOT NULL,
  record_count    INT           NOT NULL,
  cross_category  TINYINT(1)    NOT NULL DEFAULT 0,
  created_at      DATETIME(3)   NOT NULL,
  KEY idx_owner (owner_id, created_at)

```

`source_books` 保存合并当时的快照：`[{"id":3,"name":"2019 礼簿","category":"huopao","recordCount":42}]`。之后源本子改名，也不影响追溯。

### recognize_task

```sql
CREATE TABLE recognize_task (
  id             BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  owner_id       BIGINT UNSIGNED NOT NULL,
  image_path     VARCHAR(255) NOT NULL,
  image_sha256   CHAR(64)     NOT NULL,
  image_size     INT          NOT NULL,
  status         VARCHAR(16)  NOT NULL,
  provider       VARCHAR(32)  NOT NULL DEFAULT '',
  model          VARCHAR(64)  NOT NULL DEFAULT '',
  raw_response   MEDIUMTEXT   NULL,
  items          JSON         NULL,
  error_message  VARCHAR(512) NOT NULL DEFAULT '',
  committed      TINYINT(1)   NOT NULL DEFAULT 0,
  created_at     DATETIME(3)  NOT NULL,
  finished_at    DATETIME(3)  NULL,
  KEY idx_owner_created (owner_id, created_at)
);
```

- `status` 取值：`pending`、`running`、`succeeded`、`failed`。
- `raw_response` 保存模型原始回复，用于回溯；`items` 保存解析校验后的结构化结果。
- 同一张图（`image_sha256` 相同）重复上传时，前端提示"这张图 X 月 X 日识别过"，用户可以选择查看上次结果或重新识别。

## 业务规则落到数据层

### 名目推断

前端没有传 `item_kind` 时，后端按以下顺序推断：

1. 填写了礼品名称，且现金金额为 0：推断为 `gift`
1. 本子类别是 `huopao`：推断为 `huopao`
1. 其他情况：推断为 `cash`

### 状态默认值

| 场景 | 默认状态 |
| --- | --- |
| 新建收方向记录 | `pending` |
| 新建送方向的普通记录 | `pending` |
| 通过还礼流程新建的送方向记录 | `none` |

用户可以在表单里手动改成其他状态。

### 合并归属

合并只改 `record.book_id` 和源本子的 `status`、`merged_into_id`。曾经合并进源本子的旧本子，其 `merged_into_id` 也要改成新的目标本子，让合并关系保持一层，查询时不用递归。

### 纸本还礼标注

纸本标注"11年国庆 孙女 100元 火炮20元"写在张三那一行（收礼 50）旁边，落库结果如下：

| 表 | 内容 |
| --- | --- |
| record（原收礼） | `paper_note` = 标注原文，`status` = repaid |
| event | 名称"孙女结婚"，`host` = other，`host_person_id` = 张三，`event_date` = 2011-10-01，`date_precision` = month |
| record（送礼 1） | 张三、上面的事项、原收礼所在本子、`item_kind` = cash、10000 分、`occurred_on` = 2011-10-01、`date_precision` = month、`status` = none |
| record（送礼 2） | 同上，`item_kind` = huopao、2000 分 |
| record_repay | 两条：送礼 1、送礼 2 分别关联原收礼 |

规则：

- 还礼记录放在原收礼所在的本子里，因为纸本上标注就写在这本礼簿上。
- 节令按公历近似月份换算：正月→2 月，腊月→1 月（次年），端午→6 月，中秋→9 月，国庆→10 月，五一→5 月，春节、过年→2 月；精度都记为 month。原文保留在 `paper_note` 中，有需要时以原文为准。
- 两位年份按 19xx 或 20xx 补全：小于等于当前年份后两位的视为 20xx，否则视为 19xx。
- 一条标注含多次还礼（纸本上常写成两行）时，每次还礼各自按上表生成事项、送礼记录和关联，它们都关联到同一条原收礼记录，`paper_note` 保存完整原文。
- 标注只有"已还""✓"这类记号时，只更新原记录的 `status` 和 `paper_note`，不生成送礼记录。
- "还欠"不单独存储，就是仍为 pending 的收礼记录，口径与待还清单相同。

## 统计口径 SQL

下面所有统计都只对 `record.total_cent` 求和，以记录明细为单位，不按本子去重。

### 人维度汇总

```sql
SELECT
  SUM(CASE WHEN direction = 'in'  THEN total_cent ELSE 0 END) AS in_cent,
  SUM(CASE WHEN direction = 'out' THEN total_cent ELSE 0 END) AS out_cent,
  SUM(CASE WHEN direction = 'in' AND status = 'pending' THEN 1 ELSE 0 END) AS pending_count,
  COUNT(*) AS record_count,
  MAX(occurred_on) AS last_date
FROM record
WHERE owner_id = ? AND person_id = ?;
```

净差额等于 `in_cent - out_cent`。

### 事项内按人聚合

```sql
SELECT person_id,
  SUM(CASE WHEN direction = 'in'  THEN total_cent ELSE 0 END) AS in_cent,
  SUM(CASE WHEN direction = 'out' THEN total_cent ELSE 0 END) AS out_cent,
  SUM(CASE WHEN direction = 'in' AND status = 'pending' THEN 1 ELSE 0 END) AS pending_count
FROM record
WHERE owner_id = ? AND event_id = ?
GROUP BY person_id
ORDER BY in_cent DESC;
```

分本子、分名目的明细，再按 `(person_id, book_id, item_kind)` 分组查一次，由后端组装成树形结构。

### 我欠别人

```sql
SELECT person_id, COUNT(*) AS cnt, SUM(total_cent) AS total_cent, MIN(occurred_on) AS earliest
FROM record
WHERE owner_id = ? AND direction = 'in' AND status = 'pending'
GROUP BY person_id
ORDER BY earliest ASC;
```

### 别人欠我

```sql
SELECT r.person_id, COUNT(*) AS cnt, SUM(r.total_cent) AS total_cent, MIN(r.occurred_on) AS earliest
FROM record r
WHERE r.owner_id = ? AND r.direction = 'out' AND r.status = 'pending'
  AND NOT EXISTS (SELECT 1 FROM record_repay rp WHERE rp.repay_record_id = r.id)
GROUP BY r.person_id
ORDER BY earliest ASC;
```

### 按年按月

```sql
SELECT MONTH(occurred_on) AS m, direction, SUM(total_cent) AS total_cent, COUNT(*) AS cnt
FROM record
WHERE owner_id = ? AND occurred_on >= ? AND occurred_on < ?
GROUP BY m, direction;
```

涉及人数单独查：`COUNT(DISTINCT person_id)`。

### 按名目拆分

```sql
SELECT item_kind, direction, SUM(total_cent) AS total_cent, COUNT(*) AS cnt
FROM record
WHERE owner_id = ? AND book_id = ?
GROUP BY item_kind, direction;
```

## 建表快照

沿用仓库约定：建表 SQL 以全量快照维护在 `backend/migrate/mysql/schema.sql`，服务启动不自动迁移，改 schema 直接改快照。快照包含本文档全部表结构和下面的种子数据：

- `app_user(1)`
- 内置 `dict_item`
- 占位事项"纸本未注明事项"（`placeholder=1`，owner 为 1）

本机已有数据时，修改表结构要另外手写一次性 `ALTER` 语句执行，快照本身只描述最终结构。第二阶段上线后，如果需要保留线上数据，再评估引入版本化迁移。
