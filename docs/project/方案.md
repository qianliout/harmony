# 人情往来账本 — 精简实施方案

## 0. 目标与原则

在现有代码上做减法，目标产品见 `docs/project/需求.md`。只保留记账、统一、查询、修改、识别五项能力，删除事项、回礼、统计、纸本工具、导入导出、设置、登录等功能。

原则：删到不再保留，不是隐藏入口；先备份数据库，再改表结构、删代码。

## 1. 目标数据模型

只保留四张业务表，单用户固定 `owner_id = 1`。

```sql
CREATE TABLE IF NOT EXISTS app_user (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  nickname   TEXT NOT NULL DEFAULT '',
  created_at DATETIME NOT NULL,
  updated_at DATETIME NOT NULL
);

CREATE TABLE IF NOT EXISTS person (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id      INTEGER NOT NULL,
  name          TEXT NOT NULL,
  name_pinyin   TEXT NOT NULL DEFAULT '',
  name_initials TEXT NOT NULL DEFAULT '',
  created_at    DATETIME NOT NULL,
  updated_at    DATETIME NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_person_owner_name ON person(owner_id, name);

CREATE TABLE IF NOT EXISTS book (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id    INTEGER NOT NULL,
  name        TEXT NOT NULL,
  category    TEXT NOT NULL DEFAULT 'renqing',
  description TEXT NOT NULL DEFAULT '',
  created_at  DATETIME NOT NULL,
  updated_at  DATETIME NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_book_owner_name ON book(owner_id, name);

CREATE TABLE IF NOT EXISTS record (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id    INTEGER NOT NULL,
  person_id   INTEGER NOT NULL,
  book_id     INTEGER NULL,
  direction   TEXT NOT NULL,
  amount_cent INTEGER NOT NULL DEFAULT 0,
  matter      TEXT NOT NULL DEFAULT '',
  note        TEXT NOT NULL DEFAULT '',
  occurred_on TEXT NOT NULL,
  created_at  DATETIME NOT NULL,
  updated_at  DATETIME NOT NULL,
  CONSTRAINT ck_record_direction CHECK (direction IN ('in', 'out')),
  CONSTRAINT ck_record_amount CHECK (amount_cent >= 0),
  CONSTRAINT ck_record_in_has_book CHECK (direction <> 'in' OR book_id IS NOT NULL)
);
CREATE INDEX IF NOT EXISTS idx_record_owner_person ON record(owner_id, person_id, occurred_on);
CREATE INDEX IF NOT EXISTS idx_record_owner_book ON record(owner_id, book_id, occurred_on);
CREATE INDEX IF NOT EXISTS idx_record_owner_direction ON record(owner_id, direction, occurred_on);

CREATE TABLE IF NOT EXISTS recognize_task (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  owner_id      INTEGER NOT NULL,
  image_path    TEXT NOT NULL,
  image_sha256  TEXT NOT NULL,
  image_size    INTEGER NOT NULL,
  status        TEXT NOT NULL,
  provider      TEXT NOT NULL DEFAULT '',
  model         TEXT NOT NULL DEFAULT '',
  raw_response  TEXT NULL,
  items         TEXT NULL,
  error_message TEXT NOT NULL DEFAULT '',
  committed     INTEGER NOT NULL DEFAULT 0,
  created_at    DATETIME NOT NULL,
  finished_at   DATETIME NULL
);
CREATE INDEX IF NOT EXISTS idx_recognize_task_owner_created ON recognize_task(owner_id, created_at);
```

字段说明：

- 收（in）必须有 `book_id`；送（out）的 `book_id` 为空，用 `matter` 记事情。
- 礼品、火炮等补充信息写在 `note`，不单独设字段。
- 礼簿 `category` 预置 renqing、huopao、other，前端允许输入自定义值。

删除的表：`auth_token`、`dict_item`、`event`、`record_repay`、`paper_page_check`、`book_merge_log`、`user_setting`。

## 2. 后端改动

### 2.1 保留模块

- `component/person`、`component/book`、`component/record`、`component/recognize`、`component/health`。
- `infra`：logger、response、rdb、model、utils、consts。
- `component/config`：保留 server、database、storage、recognize、backup；删除 auth、wechat。

### 2.2 删除模块

- `component/auth`、`component/dict`、`component/event`、`component/search`、`component/setting`、`component/stats`、`component/transfer`、`component/view`。
- 对应 `infra/model` 下的 auth、dict、event、search、setting、stats、transfer、view。
- `infra/middleware` 中的 Auth、PlatformGuard、AdminOnly 一并删除；请求固定按 `owner_id = 1` 处理。
- `cmd/harmony` 删除 `token` 子命令，保留 `migrate`、`backup` 子命令。

### 2.3 接口

```text
GET    /api/v1/health
GET    /api/v1/persons
POST   /api/v1/persons
PUT    /api/v1/persons/:id
DELETE /api/v1/persons/:id
GET    /api/v1/books
POST   /api/v1/books
PUT    /api/v1/books/:id
DELETE /api/v1/books/:id
GET    /api/v1/records
POST   /api/v1/records
PUT    /api/v1/records/:id
DELETE /api/v1/records/:id
GET    /api/v1/records/summary
POST   /api/v1/recognize/tasks
GET    /api/v1/recognize/tasks/:id
POST   /api/v1/recognize/tasks/:id/commit
GET    /api/v1/recognize/tasks/:id/image
```

说明：`records` 列表统一承载总账、礼簿详情、亲友详情三种视图，通过 `personId`、`bookId`、`direction`、`from`、`to`、`keyword` 过滤；`summary` 返回总收、总送、笔数，支持同样的过滤条件。金额单位为分，时间字段用 `int64` 毫秒，接口统一返回 HTTP 200 与业务码 `code`。

## 3. 前端改动

### 3.1 页面

保留并精简为六个页面：

- 总账（复用现有 records 页面，改名，作为首页）。
- 礼簿列表、礼簿详情。
- 亲友列表、亲友详情。
- 记一笔表单。
- 识别页。

删除页面：

- H5 `sub-web`：events、event、repay、stats、notes、pages、settings、recognize-history、login。
- 小程序分包：sub-event、sub-book 下的 merge、merged、pages、sub-record 下的 notes、sub-misc 下的 pending、stats、transfer、settings、sub-auth。
- 工作台 HomeView 删除，总账作为首页；小程序 tabBar 从四个减到三个：总账、亲友、礼簿。

### 3.2 API 模块

保留：`http.ts`、`types.ts`、`person.ts`、`book.ts`、`record.ts`、`recognize.ts`。

删除：`auth.ts`、`dict.ts`、`event.ts`、`search.ts`、`setting.ts`、`stats.ts`、`transfer.ts`、`view.ts`。

### 3.3 组件与抽屉

保留：WebTable、WebReviewTable、Modal、PageHead、Pager、PersonCell、WebIcon、SectionHead、Segmented、StatCard。

删除：MergeDialog、PaperAnnoDrawer、RepayDrawer。

精简：EntryDrawer 改为六个字段（方向、人、礼簿或事情、金额、日期、备注）；RecordDrawer 保留编辑与删除。

### 3.4 识别核对表

WebReviewTable 精简为四列：确认、姓名、金额、备注；大写金额并在金额下方，序号并在姓名里。写入前只选礼簿和方向，不选事项。

## 4. 数据迁移

1. 备份 `backend/data/harmony.db` 到 `backend/data/backups/`。
2. 因字段变化大，按新快照重建库，不使用增量迁移。
3. 若旧库有真实数据，用一次性脚本迁移：

```text
person  <- name
book    <- name、category、description
record  <- person_id、book_id、direction、amount_cent、occurred_on、note
          事情取 event.name，备注取 remark
```

丢弃事项、回礼、纸本、名目、礼品估价、合并历史等数据。旧库是测试数据时，直接删除重建。

## 5. 分步实施顺序

1. 重写需求文档和实施方案，删除旧设计文档。
2. 重写 `backend/migrate/sqlite/schema.sql`，重建本地库。
3. 后端：删模块、改 person/book/record 模型与接口、去掉鉴权中间件，跑通 `CGO_ENABLED=0 go build ./...`、`go vet ./...`、`go test ./test`。
4. 前端：删页面和接口模块、精简记一笔和识别核对表，跑通 `pnpm build`。
5. 重新 `make release` 部署到本机，浏览器验证。
6. 更新根目录 README 与部署说明；后续小程序只做总账、亲友、礼簿三页。
