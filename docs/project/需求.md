# 人情往来账本 — 需求文档（精简版）

## 0. 文档说明

本文档是唯一的产品需求依据。目标是把多本纸质人情礼簿数字化，统一成一份电子总账：能记、能查、能改。

- 记录别人来我家、我去别人家的每一笔往来。
- 支持按礼簿看、按人看、全局统一看。
- 支持图片识别录入，减少手工录入。

## 1. 核心概念

- 礼簿：对应一本纸质礼簿，有名称、种类和详细信息；只记录“别人来我家”的收礼。
- 人：往来对象，全局唯一。
- 记录：一条往来明细，包含方向、人、金额、日期、备注；收礼挂在某本礼簿下，送礼不挂礼簿，只记事情。
- 总账：所有礼簿合并后的统一视图，收送都在其中。
- 识别：上传礼簿照片，识别出姓名和金额，核对后写入记录。

## 2. 数据需求

### 2.1 礼簿

需记录：名称、种类、备注。

- 种类：预置人情礼、火炮、其他，可自定义。
- 备注：这本礼簿的详细信息，如存放位置、起始年份。

### 2.2 人

需记录：姓名。

约束：人全局唯一，同名不重复创建；支持按姓名或拼音首字母查找。

### 2.3 记录

需记录：方向、人、金额、日期、备注；收礼额外记礼簿，送礼额外记事情。

- 方向：收（别人来我家）/ 送（我去别人家）。
- 金额：必填，非负，单位为元。
- 日期：默认当天，可改。
- 备注：可选，写礼品、火炮等补充信息。
- 事情：送方向填写，自由文本，如“张三升学酒”。

## 3. 功能需求

### 3.1 总账

1. 展示所有礼簿合并后的全部记录，收送都显示。
2. 支持按礼簿、人、方向、日期、关键词筛选。
3. 顶部显示总收、总送、笔数。
4. 每行支持编辑、删除。

### 3.2 礼簿

1. 礼簿列表，可按名称、种类查询。
2. 新建、编辑、删除礼簿。
3. 礼簿详情：显示礼簿信息和这本礼簿里的所有收礼记录。

### 3.3 亲友

1. 亲友列表，可按姓名、拼音查找。
2. 亲友详情：显示这个人的全部往来，收送都显示。

### 3.4 记录

1. 记一笔：方向、人、金额、日期、备注；收时选礼簿，送时填事情。
2. 编辑、删除任意一条记录。

### 3.5 识别

1. 上传礼簿照片，识别出姓名和金额。
2. 逐条核对、修正后写入，写入前选择礼簿和方向。
3. 识别只在本机 Web 端提供，微信小程序不提供。

## 4. 页面需求

1. 总账页：记录表、筛选、总计、记一笔入口、识别入口。
2. 礼簿列表页、礼簿详情页。
3. 亲友列表页、亲友详情页。
4. 记一笔表单。
5. 识别页：上传、识别中、核对、写入。

## 5. 业务规则

1. 方向只分收、送；收有礼簿，送有事不挂礼簿。
2. 金额非负；礼品信息写在备注里，不单独设字段。
3. 同一人全局唯一，不因礼簿不同而重复创建。
4. 删除礼簿、人前校验关联记录，有关联时阻止删除。
5. 删除记录需要确认提示。

## 6. 使用形态

1. 当前阶段为本机 Web 端，浏览器访问。
2. 最终提供微信小程序，两端功能一致。
3. 识别仅在 Web 端，小程序不做识别。

## 7. 验收清单

- [ ] 可新建多本礼簿，每本有名称、种类、备注。
- [ ] 收礼记录挂在指定礼簿，送礼记录不挂礼簿、只记事情。
- [ ] 总账能同时显示收送，并按礼簿、人、方向、日期、关键词筛选。
- [ ] 礼簿详情只显示这本礼簿里的收礼记录。
- [ ] 亲友详情显示这个人的全部收送记录。
- [ ] 每条记录可新增、编辑、删除。
- [ ] 图片可上传、识别、核对后写入。
