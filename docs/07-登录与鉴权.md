# 登录与鉴权

服务部署到公网之后，必须先登录才能读写数据。本文档替代 `04-小程序适配.md` 原"登录"一节的设计，补全了令牌存储、扫码确认、图片访问和管理员规则。

## 目标

- 小程序：打开即自动登录，用户无感知。
- 网页：用手机微信扫一下码、在小程序里点"确认"即可登录，不需要账号密码。
- 每个微信用户只能看到自己的账本，`owner_id` 由登录态决定。
- 识别（会产生模型费用）只对管理员开放。
- 礼簿原图只能由图片的主人查看。

## 小程序信息

| 项 | 值 |
| --- | --- |
| AppID | `wx348e5ad03f9cd6ba` |
| 主体 | 个人 |
| AppSecret | 在微信公众平台"开发管理 → 开发设置"中生成，只放在服务器环境变量 `HARMONY_WECHAT_APP_SECRET` 中 |

AppID 不是机密，写进 `frontend/src/manifest.json` 的 `mp-weixin.appid` 和后端配置；AppSecret 是机密，不写进任何文件。

## 令牌

### 形式

使用不透明随机令牌，不使用 JWT：

- 令牌是 32 字节随机数的 base64url 编码，43 个字符。
- 数据库只保存令牌的 SHA-256，泄露数据库文件也拿不到可用令牌。
- 吊销就是删一行，不需要黑名单。

单进程、单库的部署下，每个请求查一次 `auth_token` 走唯一索引，开销可以忽略，没有必要引入 JWT 的签名和续期复杂度。

### 表结构

```sql
CREATE TABLE IF NOT EXISTS auth_token (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id      INTEGER NOT NULL,
  token_hash   TEXT    NOT NULL,
  client       TEXT    NOT NULL,           -- mp 或 h5
  device       TEXT    NOT NULL DEFAULT '', -- 浏览器 UA 摘要或"微信小程序"
  created_at   TEXT    NOT NULL,
  expires_at   TEXT    NOT NULL,
  last_used_at TEXT    NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS uk_auth_token_hash ON auth_token(token_hash);
CREATE INDEX IF NOT EXISTS idx_auth_token_user ON auth_token(user_id);
```

`app_user` 表结构不变，`openid` 已有唯一索引。

### 有效期

| 客户端 | 有效期 | 续期 |
| --- | --- | --- |
| 小程序 | 30 天 | 剩余不足 7 天时，下一次请求自动把 `expires_at` 延长到 30 天后 |
| 网页 | 14 天 | 同上，延长到 14 天后 |

续期在鉴权中间件里完成，客户端无感知。`last_used_at` 最多每小时更新一次，避免每个请求都写库。过期令牌由每日备份任务顺带清理。

## 鉴权中间件

`infra/middleware.Owner` 改为 `Auth`，挂在 `/api/v1` 下除白名单外的所有路由：

1. 读取 `Authorization: Bearer <token>`，没有就返回 `code=401`。
1. 计算 SHA-256，查 `auth_token`；查不到或已过期返回 `code=401`。
1. 把 `user_id` 作为 ownerID 写入 ctx，业务代码继续用 `middleware.OwnerID(ctx)`，不需要改。
1. 按上节规则续期。

白名单（不需要登录）：

| 路由 | 原因 |
| --- | --- |
| `GET /health` | 部署后探活 |
| `POST /auth/wx-login` | 小程序换令牌 |
| `POST /auth/web-ticket`、`GET /auth/web-ticket` | 网页发起扫码登录、轮询结果 |
| `GET /recognize/tasks/image` | 用签名校验，见"原图访问" |

`middleware.OwnerID` 在 ctx 里取不到值时不再回落到 1，而是返回 0；store 层用 0 查不到任何数据，避免鉴权漏挂时意外读到管理员的账本。`DefaultOwnerID` 常量删除。

## 小程序登录

```text
小程序启动 ─> uni.login 得到 code
          ─> POST /auth/wx-login {code}
          ─> 后端调用 code2Session(appid, secret, code) 得到 openid
          ─> 按 openid 查 app_user；没有就新建并初始化（见"新用户初始化"）
          ─> 签发 client=mp 的令牌，返回 {token, expiresAt, user}
          ─> 小程序 uni.setStorageSync('token', token)
```

- `session_key` 不保存：本应用不解密任何微信加密数据。
- code2Session 失败（code 无效、频率限制）返回 `code=502`，前端提示"登录失败，下拉重试"。
- 请求层收到 `code=401` 时，清掉本地令牌，重新走一次上面的流程，然后重放原请求；重放仍然 401 就停止，避免死循环。

## 网页扫码登录

### 流程

```text
网页                         后端                          小程序
 │ POST /auth/web-ticket ──>  │ 生成 ticket（内存，2 分钟）     │
 │ <── {ticket, qrImage}      │ 调 getUnlimited 生成小程序码    │
 │ 显示小程序码，每 2 秒轮询                                  │
 │ GET /auth/web-ticket ───>  │ status=waiting                │
 │                            │   <── 微信扫码打开 sub-auth/confirm?scene=ticket
 │                            │   <── POST /auth/web-ticket/scan?ticket=（带小程序令牌）
 │ GET ... status=scanned     │                                │ 显示"在电脑浏览器上登录？"
 │ 页面显示"已扫码，请在手机上确认"                             │ 用户点"确认登录"
 │                            │   <── POST /auth/web-ticket/confirm?ticket=
 │ GET ... status=confirmed   │ 签发 client=h5 的令牌，与小程序同一 user
 │ <── {token}                │ ticket 立即作废                 │
 │ 存令牌，进入首页                                             │
```

### ticket

- 存在进程内存里（`sync.Map` 加过期清理协程），不落库：单进程部署，重启后丢失也只是让用户重新扫一次。
- ticket 是 16 字节随机数的十六进制，32 个字符，正好是小程序码 `scene` 参数的长度上限。
- 状态：`waiting` → `scanned` → `confirmed`；用户在小程序里点"取消"则为 `canceled`；超过 2 分钟为 `expired`。
- 令牌只在第一次轮询到 `confirmed` 时返回一次，之后这个 ticket 被删除。
- 同一 IP 每分钟最多创建 10 个 ticket，超过返回 `code=429`。

### 小程序码

网页显示的是小程序码，而不是普通二维码。好处是用户直接用微信"扫一扫"就能打开小程序的确认页，不需要先进小程序再找扫码入口。

- 后端调用 `POST https://api.weixin.qq.com/wxa/getwxacodeunlimit`，参数 `scene=<ticket>`、`page=sub-auth/confirm`、`check_path=false`、`env_version` 取配置值（开发阶段 `develop`，体验版 `trial`，上线后 `release`）。
- 调用需要 `access_token`，用 `stable_token` 接口获取，缓存在内存里，提前 5 分钟刷新。
- 生成的图片以 base64 返回给网页，不落盘。
- 生成失败时（例如小程序还没发布、`page` 不存在）降级为普通二维码，内容为 `harmony-login:<ticket>`，用户在小程序"我的 → 扫码登录网页版"里扫。两种码由后端在响应里用 `qrKind` 区分。

### 确认页

`sub-auth/confirm` 只编进小程序（`#ifdef MP-WEIXIN`）：

- `onLoad` 从 `scene` 里取 ticket，调用 `scan` 接口。
- 页面显示：电脑图标、"在电脑浏览器上登录人情往来账本"、发起时间、"确认登录"主按钮和"取消"次按钮。
- ticket 已过期时显示"二维码已过期，请在电脑上刷新"。

### 访问令牌登录

在小程序审核通过之前，没法用扫码登录网页。为此提供一个命令行签发的兜底方式：

```bash
./harmony token issue -config /etc/harmony/config.yaml -user 1 -days 14
```

命令在服务器上执行，输出一个 h5 令牌。网页登录页底部有一个默认收起的"使用访问令牌登录"入口，粘贴令牌即可登录。只有能登录服务器的人才能签发令牌，不对外暴露任何接口。

## 管理员与数据认领

### 管理员

`app_user.id = 1` 是管理员，也就是你自己。配置项：

```yaml
auth:
  adminUserIds: [1]
```

管理员独有的能力只有识别：识别路由在 `PlatformGuard` 之外再挂一个 `AdminOnly` 中间件，非管理员调用返回 `code=403`，网页首页对非管理员隐藏识别入口（`GET /auth/me` 返回 `isAdmin`）。

### 第一个登录的人认领管理员

全新部署时，`schema.sql` 种子数据里的 `app_user(1)` 没有 openid。小程序登录时：

1. 按 openid 查不到用户，并且 `app_user(1).openid` 为空，就把这个 openid 写进 `app_user(1)`，登录为管理员。
1. 否则新建用户。

这个规则的安全前提是：小程序正式发布之前，只有开发者和体验成员能打开它。部署完成后，用你自己的微信打开体验版登录一次，管理员就被认领了，再提交审核。部署手册把这一步列为必做项，见 `09-部署上线.md`。

### 其他人

个人主体的小程序发布后任何人都能打开，审核人员也需要能正常使用。所以不关闭注册：

- 其他人登录后得到一个全新的、空的账本，和管理员的数据互相隔离。
- 他们能使用除识别以外的全部功能；小程序本来就没有识别入口。
- 网页登录同样开放，但网页首页对非管理员不显示识别入口。

## 新用户初始化

每个用户都需要自己的内置字典和占位事项，否则记账页的名目、本子类别是空的。新建 `app_user` 时在同一个事务里：

1. 插入内置 `dict_item`：本子类别"人情礼、火炮、其他"，记录名目"现金、火炮、实物礼品"。
1. 插入占位事项"纸本未注明事项"（`placeholder=1`）。

内置数据的定义从 `schema.sql` 的种子语句里抽到 Go 常量 `consts.BuiltinDictItems`，`schema.sql` 只保留给 `owner_id=1` 的那一份，两处共用同一份定义，由一个测试断言保持一致。

## 原图访问

现状：`main.go` 用 `engine.Static("/uploads", ...)` 把原图目录直接暴露出去，知道路径的人都能看到。礼簿照片上全是亲友姓名和金额，上线前必须收回。

改为签名 URL：

1. 删除 `/uploads` 静态路由。
1. 识别任务详情接口返回的 `imageUrl` 改为 `/api/v1/recognize/tasks/image?id=12&exp=1762600000000&sig=...`。
1. `sig = base64url(HMAC-SHA256(secret, "<id>.<ownerID>.<exp>"))`，`exp` 是 1 小时后的毫秒时间戳。
1. 图片接口不要求 `Authorization` 头（`<image>` 标签发不出这个头），只校验签名、有效期，并按 id 查任务、确认 `owner_id` 与签名中一致，然后返回文件，响应头 `Cache-Control: private, max-age=3600`。

`secret` 来自环境变量 `HARMONY_AUTH_SECRET`（32 字节以上随机串）。未设置时服务拒绝启动，只有 `server.mode=debug` 时允许用固定的开发值。

## 平台边界

识别的边界由三层共同保证：

| 层 | 机制 | 防的是什么 |
| --- | --- | --- |
| 编译 | `#ifdef H5`，小程序产物里没有识别代码 | 小程序界面上不可能出现识别 |
| 平台头 | `PlatformGuard` 校验 `X-Client-Platform: h5` | 正常客户端误调用 |
| 权限 | `AdminOnly` 只允许管理员 | 伪造请求头的调用者 |

平台头可以伪造，所以真正的保护是登录加管理员校验；加上 `06-识别接入千问.md` 中的每日次数上限，即使管理员令牌泄露，费用也有上限。

## 新增接口

| 方法 | 路径 | 登录 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/wx-login` | 否 | `{code}` → `{token, expiresAt, user}` |
| POST | `/auth/web-ticket` | 否 | → `{ticket, qrKind, qrImage, expiresAt}` |
| GET | `/auth/web-ticket?ticket=` | 否 | → `{status, token?}` |
| POST | `/auth/web-ticket/scan?ticket=` | 是（小程序） | 标记已扫码，返回发起时间 |
| POST | `/auth/web-ticket/confirm?ticket=` | 是（小程序） | 确认登录 |
| POST | `/auth/web-ticket/cancel?ticket=` | 是（小程序） | 取消 |
| GET | `/auth/me` | 是 | `{user, isAdmin, client}` |
| GET | `/auth/sessions` | 是 | 当前用户全部登录设备 |
| DELETE | `/auth/sessions?id=` | 是 | 让某个设备下线 |
| POST | `/auth/logout` | 是 | 删除当前令牌 |

新增领域 `component/auth`，分层与其他领域相同；微信接口调用封装在 `component/auth/service/wechat.go`，通过接口注入，测试时替换为假实现。

## 测试

| 用例 | 断言 |
| --- | --- |
| 无令牌 | 业务接口返回 401；健康检查返回 200 |
| 过期令牌 | 返回 401 |
| 续期 | 剩余 6 天的令牌请求一次后，`expires_at` 变为 30 天后 |
| 数据隔离 | 用户 A 创建的记录，用户 B 查列表、查详情、搜索、统计都看不到；B 按 id 修改返回 404 |
| 认领 | 全新库第一个 wx-login 绑定到 user 1；第二个 openid 新建 user 2，并带有内置字典和占位事项 |
| 扫码 | waiting → scanned → confirmed，令牌只返回一次；第二次轮询返回 expired |
| 管理员 | user 2 调用识别返回 403 |
| 原图签名 | 篡改 id、exp、sig 任一项返回 403；过期返回 403；用 user 2 的签名访问 user 1 的图返回 403 |

## 验收

1. 小程序冷启动后不需要任何操作就能看到首页数据。
1. 电脑浏览器打开网页，出现小程序码；手机微信扫码后点确认，网页在 2 秒内进入首页。
1. 在小程序记一笔，刷新网页能看到；反过来同样成立。
1. 直接访问旧的 `/uploads/...` 路径返回 404；复制签名 URL 一小时后再打开返回 403。
1. 用另一个微信号登录，看到的是空账本，网页首页没有识别入口。
