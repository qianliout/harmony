# 小程序适配

第二阶段在同一套 `frontend/` 源码上编译出微信小程序。本文档说明两端的差异如何处理，以及上线前要做的准备。

## 功能边界

| 功能 | H5 | 小程序 | 实现方式 |
| --- | --- | --- | --- |
| 记账、查询、统计、合并、导入导出 | 有 | 有 | 共用代码 |
| 图片上传、识别、识别结果核对 | 有 | 无 | `#ifdef H5` 条件编译 |
| 登录 | 扫码登录 | 微信登录 | 见下文 |
| 导出 | 浏览器下载 | 下载后打开文档 | `#ifdef` 分支 |
| 导入 | 选择本地文件 | 从聊天记录选择文件 | `#ifdef` 分支 |

## 条件编译规则

识别功能的边界要靠编译保证，而不是运行时判断。具体规则：

- `sub-recognize` 分包只在 H5 中注册。在 `pages.json` 中，用 `// #ifdef H5` 把这个分包的声明包起来。
- `api/recognize.ts` 整个文件的内容用 `// #ifdef H5` 包起来。
- 所有识别入口（首页宫格、记录详情的"查看原图"）的模板都用 `<!-- #ifdef H5 -->` 包起来。
- 后端识别路由挂 `PlatformGuard` 中间件作为兜底。

验收方法：编译小程序后，在产物目录中执行下面的搜索，必须没有任何结果。

```bash
grep -rniE "recognize|识别" frontend/dist/build/mp-weixin --include=*.js --include=*.json --include=*.wxml
```

把这条命令加进 CI 或者 `make release-mp`，搜索有结果时构建失败。

## 登录

### 小程序：微信登录

1. 小程序启动时调用 `uni.login` 拿到 `code`。
1. 调用 `POST /api/v1/auth/wx-login {code}`。后端用 code 调用微信 `code2Session` 换取 openid，按 openid 查找或新建 `app_user`，签发 token。
1. token 有效期 30 天，存放在 `uni.setStorageSync('token')` 中，请求时放进 `Authorization` 头。
1. 后端返回 `code=401` 时，请求层自动重新登录一次，然后重试原请求。

### Web：小程序扫码登录

Web 端不接入微信开放平台（开放平台需要单独认证，成本高）。改用小程序扫码授权的方式：

1. Web 登录页调用 `POST /auth/web-ticket`，后端生成一个 ticket，有效期 2 分钟，状态为 waiting。
1. Web 把 `harmony-login:<ticket>` 渲染成二维码，并每 2 秒轮询一次 `GET /auth/web-ticket?ticket=`。
1. 用户在小程序"我的"页面点击"扫码登录网页版"，调用 `uni.scanCode` 扫描二维码，然后显示确认页"在浏览器上登录？"。
1. 用户确认后，小程序调用 `POST /auth/web-ticket/confirm?ticket=`，后端把 ticket 和当前用户绑定。
1. Web 下一次轮询拿到 token，登录完成。

小程序码内容不包含任何身份信息，ticket 只能使用一次。

### 第一阶段的数据迁移到微信账号

第一阶段所有数据都属于 `owner_id=1`。第二阶段第一个用微信登录的用户如果确认"认领本机数据"，后端执行一次 `UPDATE ... SET owner_id = 新用户 id WHERE owner_id = 1`，覆盖所有业务表，在同一个事务中完成，然后把 `app_user(1)` 标记为已认领。这个操作只提供一次，入口在"我的"页面。

## 平台差异处理

| 差异点 | 处理 |
| --- | --- |
| 网络请求 | 小程序要求 HTTPS 和已备案域名，并且要在小程序后台配置 request 合法域名。`VITE_API_BASE` 按平台使用不同的 env 文件 |
| CSS 变量 | 小程序不支持 `:root`，token 同时写在 `page` 选择器上（已在 `tokens.scss` 中处理） |
| 字体 | 小程序里没有宋体可用，印章字体在小程序上回退到系统字体，加粗显示。如果需要统一，可以把"喜奠满迁学年礼簿"8 个字子集化为 woff，用 `uni.loadFontFace` 加载，文件大约 10KB |
| 原生导航栏 | 两端都使用 `pages.json` 配置的原生导航栏，背景 `#F6F2EC` |
| 下拉刷新 | 在 `pages.json` 中为需要的页面开启 `enablePullDownRefresh` |
| 长按、左滑 | 使用 wot 的 `wd-swipe-action`，两端表现一致 |
| 震动 | 小程序 `uni.vibrateShort`；H5 中用 `#ifdef MP` 包起来，不调用 |
| 物理键盘 | 只在 H5 中监听 `keydown` |
| 文件下载 | H5 用 `a[download]`；小程序用 `uni.downloadFile` 加 `uni.openDocument` |

## 包体积

- 主包只包含 4 个 tab 页、公共组件和请求层，目标小于 1MB。
- 统计页依赖的 uCharts 只在 `sub-misc` 分包中引入，并在分包中开启 `"lazyCodeLoading": "requiredComponents"`。
- wot-design-uni 按需引入（easycom），不要全量注册。
- 不打包图片资源，图标使用 wot 自带的图标或 svg 转 base64，单个文件不超过 2KB。

## 上线准备清单

- 注册小程序，获取 AppID，填写到 `manifest.json` 的 `mp-weixin.appid`。
- 准备备案域名和 HTTPS 证书，后端部署到服务器，H5 与 API 同域部署。
- 在小程序后台配置 request 合法域名、downloadFile 合法域名。
- 后端配置 `wechat.appID`、`wechat.appSecret`，用环境变量注入，不入库。
- 用户隐私保护指引：本应用收集姓名、电话这类第三方个人信息，需要在隐私指引中说明用途和保存方式。
- 类目选择"工具 → 记账"。
- 在真机上走一遍 `fen.md` 9.3 节的验收条目。

## 回归策略

Web 端是小程序的对标环境。每次发布小程序前：

1. 在 H5 上跑完 9.1 节的全部条目。
1. 在小程序开发者工具上跑同样的条目，对比两端截图，检查是否一致。
1. 在小程序上新增一条记录，在 Web 上检查是否可见、统计是否一致；然后反过来再检查一次。
1. 执行上面的识别代码搜索，确认没有结果。
