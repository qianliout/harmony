# 前端交互与 UI 规范

本文档的目标：不需要设计稿，照着本文档和 `project/index.html` 就能写出好看、好用的界面。本文的数值都可以直接写进代码；凡是给出了数值的地方，开发时不要自己改。

## 设计原则

1. 录入要快。记一笔在 3 次点击加一次金额输入内完成；连续录入一笔只需输入姓名、金额、回车。上次用的本子、事项、日期都自动带出。
1. 金额最显眼。账本类应用里，用户扫一眼就要看到钱。金额使用独立的数字字体、更大的字号、方向色，其他信息退到次要层级。
1. 收和送靠颜色区分，不靠阅读。收用朱红，送用墨青，全应用一致。用户不用读"收""送"二字，看颜色就能分辨。
1. 还要回的人情要醒目但不吵。未回礼和对方未回统一用琥珀色：一个状态胶囊，收礼的未回礼再加一条左侧色条，不用大面积色块。
1. 先给结论，再给明细。所有详情页顶部是汇总，下面是明细；明细默认按事项或人聚合，展开后才显示分本子、分名目的数据。
1. 不让用户迷路。任何页面最多两步回到首页；破坏性操作都要确认，并且说清楚后果。

## 视觉语言

主题名"朱砂礼簿"。灵感来自纸质礼簿：暖白纸底、朱砂红、墨色文字、印章元素。整体气质是温暖、端正、克制，避免花哨的渐变和插画，靠留白、层级和少量印章元素营造质感。

三个标志性元素：

- 纸底：页面背景是暖白色，卡片是纯白色，两者有轻微色差，形成"纸上贴签"的层次感。
- 印章：事项类型用一个宋体单字放在圆角方印里表示，例如喜、奠、满、迁、学、年、礼。印章是全应用最有辨识度的图形元素。
- 首页朱砂卡：首页顶部是一张深朱砂色的汇总卡，配白色数字，是唯一一处大面积使用强色的地方。

## 布局与导航

### 导航结构

底部 tabBar 有 4 个入口，使用原生 tabBar，两端行为一致：

| Tab | 页面 | 图标含义 |
| --- | --- | --- |
| 首页 | `pages/index/index` | 屋檐 |
| 亲友 | `pages/person/list` | 双人 |
| 礼簿 | `pages/book/list` | 书本，页内分"本子"和"事项"两个分段 |
| 我的 | `pages/mine/index` | 单人 |

"记一笔"是最高频的操作，不放进 tabBar，而是在以下位置提供：

- 首页朱砂卡下方的主按钮。
- 亲友、礼簿两个 tab 页右下角的悬浮按钮（FAB）：直径 56，朱砂底，白色加号，`--shadow-float`，距离底部 tabBar 16，距右侧 16。
- 亲友详情、事项详情、本子详情的底部操作栏，这些入口会预填对应的上下文。

tabBar 样式：背景 `--c-surface`，未选中图标和文字用 `--c-ink-3`，选中时用 `--c-primary`，文字 11px。


- 导航栏使用原生导航栏，背景色 `#F6F2EC`，文字黑色。详情页如果需要在导航栏上放操作，就改用自定义导航栏组件，两端保持一致。
- 底部操作栏内最多放 2 个按钮：左边是次要按钮（白底描边），右边是主按钮（朱砂底），两者宽度比为 1:2。
- 所有吸底元素都要加上 `padding-bottom: env(safe-area-inset-bottom)`。

### H5 在桌面浏览器中的显示

`fen.md` 要求 Web 端也按手机尺寸布局。H5 在宽屏下的处理方式：

- 窗口宽度不超过 520 时，正常铺满。
- 窗口宽度超过 520 时，内容区固定为 430 宽，水平居中，两侧显示 `--c-bg` 稍深一档的底色 `#EDE6DC`，内容区加 `--shadow-float`，看起来像一部手机放在桌面上。
- uni-app H5 的 tabBar 和 fixed 元素默认铺满整个窗口宽度，在 `App.vue` 中统一限制（骨架已实现）：

```scss
/* #ifdef H5 */
@media (min-width: 521px) {
  body { background: #EDE6DC; }
  /* 根节点带 transform 后成为 fixed 元素的包含块，导航栏、tabBar、吸底栏随之限制在 430 宽内 */
  uni-app {
    position: relative; display: block; max-width: 430px; min-height: 100vh;
    margin: 0 auto; transform: translateZ(0); box-shadow: var(--shadow-float);
  }
}
/* #endif */
```

- 唯一的例外是识别相关页面：窗口宽度不低于 1024 时，切换为宽屏布局，机制与规格见 `08-Web端能力与宽屏布局.md`。

## 数据呈现规则

### 金额

| 场景 | 显示 | 规则 |
| --- | --- | --- |
| 整元 | `¥1,200` | 千分位；小数部分为 .00 时省略 |
| 有角分 | `¥1,200.50` | 保留两位小数 |
| 零 | `¥0` | |
| 只有礼品 | `被面一床` 加礼品图标，第二行 `估 ¥200` | 没有估价时只显示礼品名 |
| 现金加礼品 | `¥500` 加礼品图标 | 点开详情再看礼品 |
| 净差额 | `+¥400` 或 `−¥400` | 使用真正的减号 `−`，不用连字符 |
| 大额汇总 | `¥3.26万` | 只用于首页卡和统计卡，并且金额不低于 10 万时才缩写 |

颜色规则：

- 收方向的金额用 `--c-in`，送方向的金额用 `--c-out`。
- 汇总中的"总收""总送"跟随方向色；净差额用 `--c-ink-1`，正负号不变色。
- 在回礼清单里，金额统一用 `--c-pending`。

`utils/money.ts`：

```ts
export function formatCent(cent: number, opts: { sign?: boolean; compact?: boolean } = {}): string {
  const negative = cent < 0
  const abs = Math.abs(cent)
  let body: string
  if (opts.compact && abs >= 10_000_000) {
    body = `${trimZero((abs / 1_000_000).toFixed(2))}万`
  } else {
    const yuan = Math.floor(abs / 100)
    const fen = abs % 100
    body = yuan.toLocaleString('en-US') + (fen ? `.${String(fen).padStart(2, '0')}` : '')
  }
  const prefix = opts.sign ? (negative ? '−' : '+') : (negative ? '−' : '')
  return `${prefix}¥${body}`
}

function trimZero(s: string): string {
  return s.replace(/\.?0+$/, '')
}

export function yuanToCent(input: string): number {
  const [y, f = ''] = input.split('.')
  return Number(y || 0) * 100 + Number((f + '00').slice(0, 2))
}
```

元转分时必须用字符串拆分，不能写 `Math.round(yuan * 100)`，否则会出现浮点误差。

### 日期

| 场景 | 显示 |
| --- | --- |
| 当年日期 | `8月16日` |
| 往年日期 | `2023年8月16日` |
| 时间线分组标题 | `2024 · 8月16日` |
| 表单中 | `2024-08-16`，配星期：`2024-08-16 周五` |
| 回礼清单中的"多久前" | `3 年前`、`8 个月前`，一个月以内显示 `本月` |
| 精度为月 | `2011年10月`，当年为 `10月` |
| 精度为年 | `2011年` |

精度不是 day 的日期，后面加一个 `caption` 字号的 `约` 字，`--c-ink-3` 色，例如 `2011年10月 约`，提醒用户这是根据纸本标注推算的日期。

### 人

- 头像：圆形，背景用色板中的浅底，文字用对应的主色，内容是姓名的第一个字（`张三` 显示 `张`）。颜色按 `personId % 8` 从色板中取，同一个人在任何地方颜色都一样。尺寸：列表 40，详情页 56，选人器 32。
- 关系标签：`caption` 字号，`--c-fill` 底，`--c-ink-2` 字，圆角 `--r-xs`。

### 方向与状态

| 元素 | 样式 |
| --- | --- |
| 收标签 | `--c-in-light` 底，`--c-in` 字，文字"收"，12px，高 20，左右 6 |
| 送标签 | `--c-out-light` 底，`--c-out` 字，文字"送" |
| 未回胶囊 | `--c-pending-light` 底，`--c-pending` 字，前置 6px 实心圆点；收礼写"未回礼"，主动送礼写"对方未回" |
| 已回胶囊 | `--c-repaid-light` 底，`--c-repaid` 字，前置对勾图标；收礼写"已回礼"，主动送礼写"对方已回" |
| 不用回胶囊 | `--c-none-light` 底，`--c-none` 字，没有前置图标，文字"不用回" |
| 回礼标签 | 回礼生成的送礼记录不显示状态胶囊，改为 `--c-out-light` 底、`--c-out` 字的"回礼"标签；在记录详情中点击可跳到被回的收礼记录 |
| 未回礼行 | 只用于收礼的未回礼：行左侧 3px 宽 `--c-pending` 色条，高度为行高减 16，上下居中，圆角 2。主动送礼的对方未回不加色条，因为不需要我做什么 |

状态文字以接口返回的 `statusLabel` 为准，前端不按存储值自己拼。任何地方都不出现不带方向的"待还""已还"。

## 组件规范

组件放在 `frontend/src/components/`，使用 PascalCase 命名。每个组件只负责展示，不直接调用接口。

### Money

| prop | 类型 | 说明 |
| --- | --- | --- |
| `cent` | number | 金额 |
| `direction` | `'in' \| 'out' \| 'none'` | 决定颜色，`none` 为墨色 |
| `size` | `'display' \| 'l' \| 'm' \| 's'` | 对应字号 token |
| `sign` | boolean | 是否显示正负号 |
| `compact` | boolean | 大额是否缩写成万 |
| `tone` | `'pending'` | 回礼清单里强制使用琥珀色 |

货币符号 `¥` 的字号是数字字号的 0.7 倍，与数字底部对齐，并留 1px 间距。这个细节会让金额看起来精致很多。

- 记录发生过合并时，本子名后追加 `（原：火炮簿）`。
- 记录有纸本标注时，第二行下方再加一行标注原文：前置一个"注"字小印章（stone，s 尺寸缩到 16），文字用宋体 13px `--c-ink-2`，单行省略。标注原文是手写内容的照抄，用宋体能和系统生成的文字区分开。

亲友详情的核心组件。

```text
┌────────────────────────────────────────────┐
│ [学]  小明升学宴           他家办    收 ¥600 │  头部：印章 m、事项名 title-2、主办方标签、组合计
│       2024 · 8月16日                        │

│▌ 收  现金 · 2024 人情礼簿             ¥500 未回礼 │  明细行，高 44，没有头像

└────────────────────────────────────────────┘
```

- 组合计：组内同时有收和送时，显示两个金额 `收 ¥600  送 ¥800`。
- 合计公式行：数据来自接口的 `parts`，各部分之间用 ` + ` 连接，最后加 ` = ` 和合计。这一行是 `fen.md` 中"升学酒张三 500+100=600"要求的直接体现，不能省略。
- 组内有未回礼记录时，头部右上角显示一个 `--c-pending` 小圆点。
- 选择模式（回礼时使用）：明细行左侧出现复选框，只有收方向的未回礼记录可以勾选，其他行置灰。

### EventPicker 选事项器

结构与选人器相同。不同点：

- 没有输入时显示"最近事项"列表，每行包含印章 s、事项名、日期。
- 行内新建表单：名称、类型（7 个印章组成的网格，单选，点击时有放大回弹效果）、日期（默认今天）、主办方（自家办 / 别人家办 分段控件，默认别人家办）。地点和备注不在这里填写，以后可以到事项编辑页补充。

### BookChips 本子选择条

横向滚动的 chip 条，用于记一笔页。每个 chip 左边有一个 8px 圆点，颜色取本子类别的颜色。选中的 chip 用 `--c-primary-light` 底、`--c-primary` 字和 1px 主色描边。最后一个 chip 是"＋ 新建礼簿"。

### PaperRepaySheet 纸本回礼补录

把纸本上的一条回礼标注录成回礼记录。用于记录详情、"整理纸本标注"页和连续录入。底部弹层，高度自适应，最高为屏幕的 90%。

```text
┌─────────────────────────────┐
│ 补录回礼 · 张三               │
│ 原记录  收 ¥50 · 第 1-10 页     │  sub ink-3
│ 纸本标注                       │
│ ┌─────────────────────────┐ │
│ │ 11年国庆 孙女 100元 火炮20元  │ │  宋体，fill 底，可编辑；修改后 500ms 重新解析
│ └─────────────────────────┘ │
│ 时间   [2011 ▾] [10月 ▾] [日 ▾]    │  年、月、日三个选择器，日、月可以不选
│        (日期只到月)               │  精度提示
│ 对方事项 [孙女        ] [喜]▾      │  输入框加类型印章；有同名已有事项时下方提示"将使用已有事项"
│ 金额                           │
│   现金  [100     ]              │  每个名目一行，金额输入框
│   火炮  [20      ]   ⊖           │
│   ＋ 添加名目                    │
│ 合计 ¥120                       │
│ [✓] 同时把原记录标为已回礼          │
├─────────────────────────────┤
│ [ 只标记已回礼 ] [   保存回礼   ]    │
```

- 一条标注含多次回礼时，原文下方出现一排标签"① 2010.8.1 · ¥500""② 2011.2 · ¥50""＋"，每个标签对应一次回礼，点击切换，下面的表单编辑当前这一次；"＋"手动增加一次。底部合计显示"共 2 次 ¥550"，保存按钮写成"保存 2 次回礼"。
- 打开时调用标注解析接口，把结果预填进各字段。解析不出来的字段保持为空，并用琥珀色描边提示补全。
- 时间选择器的"日"是可选项，不选就是精度 month；连月都不选就是精度 year。不提供节令快捷按钮：标注里写的"国庆""正月"等由解析接口直接换算成月份预填，用户只需核对。

- 保存后的提示："已补录 2 笔回礼 · ¥120"。

### AmountPad 金额键盘

记一笔页的自定义键盘。不使用系统键盘，原因有三：系统键盘会遮挡表单；不同端的数字键盘表现不一致；自定义键盘可以加快捷金额。

```text
┌─────────────────────────────┐
│ [100] [200] [500] [600] [800] [1000] │ 快捷金额 chip，横向滚动
├───────┬───────┬───────┬─────┤
│   1   │   2   │   3   │  ⌫  │
├───────┼───────┼───────┼─────┤
│   4   │   5   │   6   │     │
├───────┼───────┼───────┤ 保存 │  朱砂底，跨 3 行
│   7   │   8   │   9   │     │
├───────┼───────┼───────┤     │
│   .   │   0   │  00   │     │
└───────┴───────┴───────┴─────┘
```

- 键高 52，键面白底，按下时 `--c-fill`，数字使用 `$font-num` 22px。
- 点击快捷金额：直接替换当前金额，不是累加。
- 输入规则：最多两位小数，整数部分最多 8 位；首位是 0 时再输入数字，替换掉这个 0。
- 长按 ⌫ 清空金额。
- 每次按键都触发轻震动：小程序调用 `uni.vibrateShort({ type: 'light' })`；H5 不支持就忽略。
- 快捷金额来自设置项 `quick_amounts`，在"我的 → 偏好设置"里可以修改。
- H5 桌面端：监听物理键盘，数字键、`.`、Backspace、Enter 都映射到对应的按键。

### FilterBar 与 FilterSheet

列表页的筛选分为两层：

- FilterBar：吸顶的横向 chip 条，放最常用的 3 到 4 个快捷筛选（例如 全部、未回礼、收、送），单选。"未回礼"固定表示收礼且未回礼，同时传 `direction=in&status=pending`，不会混入送礼记录。最右侧固定一个"筛选"按钮，有高级筛选生效时显示数字角标，例如"筛选 2"。
- FilterSheet：底部弹层，分两组。上面是主维度，依次为"礼簿类别、事项类型、亲友、时间"，对应 `fen.md` 第 6 节第 17 条；下面是"更多条件"，依次为"礼簿、事项、名目、方向、回礼状态"，默认折叠，有条件生效时自动展开。每段都是多选 chip，亲友段是一个打开 PersonPicker 的入口（在亲友详情页中不显示）。时间段提供"今年、去年、近 3 年、自定义"四个选项。
- 回礼状态段跟随方向：方向选了收礼，选项为未回礼、已回礼、不用回；选了送礼，选项为对方未回、对方已回、不用回；没选方向时只显示收礼的三个选项，并按收礼查询。底部两个按钮："重置"和"查看 128 条"。按钮上的数字随选择实时变化：防抖 300ms 后，请求一次只取 count 的接口。

筛选条件需要同步到页面 query，返回页面时保留筛选状态。

- ListCell：设置类的列表行，高 52，左侧图标 20 加标题，右侧值加箭头。

```text
          │ 簿 │       印章 l，stone 色，透明度 0.6
```

### Skeleton

列表和详情页首次加载时显示骨架屏，不显示转圈。骨架屏的形状要和真实内容一致：时间线骨架是 2 个分组卡片，每个分组里 2 行。骨架色块使用 `--c-fill`，带一个 1.2 秒循环的微光动画。加载时间小于 300ms 时不显示骨架屏，避免闪烁：延迟 300ms 再显示。

### ConfirmSheet

所有二次确认都用底部弹层，不使用系统 `showModal`。原因是系统弹窗在两端样式不一致，而且放不下冲突明细。

```text
┌─────────────────────────────┐
│  可能重复录入                  │  title-2
│  张三 在「升学宴」的「2024 人情 │  body ink-2
│  礼簿 · 现金」下已有 1 条记录    │
│ ┌─────────────────────────┐ │
│ │ 收 ¥500 · 2024-08-16      │ │  冲突明细卡，fill 底

└─────────────────────────────┘
```

危险操作（删除、合并）的确认按钮用 `--c-danger` 底，并且按钮文字要写明具体动作，例如"删除这笔记录"，不要只写"确定"。

## 交互模式

### 表单

- 必填项标签后面不加星号。改为把选填项收进"更多信息"折叠区，可见的字段默认都是必填。
- 校验时机：失焦时校验单个字段，提交时校验全部字段。错误文字显示在字段下方，`caption` 字号，`--c-danger` 色。提交失败时，页面滚动到第一个出错的字段。
- 提交按钮在请求期间显示加载状态并且不可点击，防止重复提交。
- 离开有修改的表单时，弹出确认"放弃未保存的修改？"。

### 软确认

请求层统一处理后端返回的 `code=409` 且 `custom.reason=need_confirm`。业务页面只需要调用 `submitWithConfirm`：

```ts
// composables/useConfirmSubmit.ts
export async function submitWithConfirm<T>(send: (confirm: boolean) => Promise<T>): Promise<T | null> {
  try {
    return await send(false)
  } catch (e) {
    if (!(e instanceof ApiError) || e.code !== 409 || e.custom?.reason !== 'need_confirm') throw e
    const ok = await openConfirmSheet(e.data as ConfirmPayload)
    if (!ok) return null
    return await send(true)
  }
}
```

用法：`await submitWithConfirm(confirm => api.createRecord({ ...form, confirm }))`，返回 null 表示用户取消了。

### 删除

1. 左滑或者在详情页"更多"菜单中点击删除。
1. 弹出 ConfirmSheet，说明后果，例如"删除后不可恢复"。
1. 后端返回 409 且 reason 为 `has_reference`（有关联）时，ConfirmSheet 的内容换成"无法删除"和原因，并提供跳转按钮，例如"查看 12 条记录"。

不提供撤销。记账数据的删除要谨慎，所以用确认来保护，而不是提供撤销。

### 列表加载

- 下拉刷新：所有列表页都支持，使用原生下拉刷新。
- 分页：滚动到距底部 200px 时自动加载下一页。底部依次显示"加载中…"或"没有更多了"，`caption` 字号，`--c-ink-3` 色。
- 从详情页返回列表时，只更新被修改的那一项，不刷新整个列表。实现方式：详情页修改后，通过 `uni.$emit('record:updated', record)` 通知列表，列表页监听这个事件。

### 反馈

| 场景 | 反馈 |
| --- | --- |
| 保存成功 | 轻提示"已保存"，1.2 秒；小程序同时轻震动 |
| 连续录入保存 | 不弹提示，改为在已录列表顶部插入新的一行，并做高亮动画 |
| 网络错误 | 轻提示"网络不太好，请重试" |
| 系统错误 | 轻提示后端返回的 msg |
| 识别失败 | 页面内错误态，不使用轻提示 |

## 文案规范

- 语气平实、亲切，像家里人记账。不使用"操作成功""数据为空"这类技术腔。
- 统一使用的术语：礼簿、礼簿类别、亲友、事项、事项类型、收礼、送礼、回礼、未回礼、已回礼、对方未回、对方已回、不用回、名目。同一个概念不能有两种叫法。
- 不使用"待还""已还""无需还""欠"：它们不带方向，看不出是谁该回谁。
- 按钮写动作：保存、回礼、合并礼簿。不写"确定""提交"。
- 数字与汉字之间加空格：`3 笔`、`共 58 人`。

空状态文案：

| 场景 | 标题 | 说明 | 按钮 |
| --- | --- | --- | --- |
| 首页没有记录 | 还没有记录 | 记下第一笔人情往来吧 | 记一笔 |
| 亲友列表为空 | 还没有亲友 | 记账时会自动添加 | 记一笔 |
| 搜索无结果 | 没找到「xx」 | 换个关键词，或试试拼音首字母 | |
| 回礼清单为空 | 人情都回完了 | 有新的收礼时会出现在这里 | |
| 筛选无结果 | 没有符合条件的记录 | | 清除筛选 |

#### 回礼流程

1. 点击"回礼"，页面进入选择模式：底部操作栏变成"已选 0 笔 · ¥0"加"下一步"按钮；FilterBar 自动切到"未回礼"；可勾选的行出现复选框。
1. 勾选记录。同一个事项分组头部有一个"全选本组"按钮，因为同一事项里的现金和火炮通常一起回。底部金额实时汇总。
1. 点击"下一步"，进入记一笔页的回礼模式（见下文），已选记录作为参数传过去。
1. 保存后返回亲友详情。被回的记录状态变为已回礼，同时播放一次绿色对勾的过渡动画。

按返回键或点击"取消"时，退出选择模式，不离开页面。

### 记一笔（新建 / 编辑 / 回礼）

一个页面兼顾三种模式，用 query 参数 `mode=create|edit|repay` 区分。

```text
┌─────────────────────────────┐
│ ‹          记一笔              │
│  ┌──────────┬──────────┐    │
│  │   收礼     │   送礼    │    │  大分段控件，高 44；选中块的颜色跟随方向
│  └──────────┴──────────┘    │
│              ¥ 500           │  display 字号，颜色跟随方向，居中
│      礼品  ⊕ 添加礼品            │  点击展开礼品名称和估价两个字段
│ ┌─────────────────────────┐ │
│ │ 亲友   [张] 张三          › │ │  点击打开 PersonPicker
│ │ 事项   [学] 小明升学宴     › │ │  点击打开 EventPicker
│ │ 礼簿   (人情礼簿)(火炮簿)(+) │ │  BookChips
│ │ 名目   现金 ▾              │ │  根据本子类别自动推断，点击可改
│ │ 日期   2024-08-16 周五    › │ │
│ │ 状态   (未回礼)(已回礼)(不用回) │ │  三段胶囊，文字随方向变化
│ │ 备注   选填                 │ │
│ └─────────────────────────┘ │
│ AmountPad                   │  固定在底部；点击金额以外的字段时收起
└─────────────────────────────┘
```

默认值：

| 字段 | 新建时默认 |
| --- | --- |
| 方向 | 收礼。从别人家办的事项进入时默认为送礼 |
| 亲友 | 从亲友详情进入时预填并锁定，否则为空 |
| 事项 | 从事项详情进入时预填；否则取设置项 `last_event_id`，但仅限这个事项在 30 天内用过 |
| 礼簿 | 设置项 `last_book_id` |
| 事项（补充） | 礼簿设置了默认事项时，优先使用默认事项，事项行后标注"礼簿默认" |
| 名目 | 按本子类别推断，规则与后端相同 |
| 日期 | 事项有日期时用事项日期，否则用今天 |
| 状态 | 收礼默认未回礼；送礼默认对方未回。切换收送时，三段胶囊的文字同步切换，选中位置不变 |

交互要点：

- 进入页面时，如果亲友为空，自动弹出 PersonPicker。这是录入顺序中的第一步：选人，然后键盘就在下面，直接输入金额，最后点"保存"。理想情况下 3 步完成。
- AmountPad 上的"保存"键就是提交按钮，不需要另外再放一个保存按钮。键盘收起时，底部操作栏出现"保存"和"保存并再记一笔"两个按钮。
- "保存并再记一笔"：保留事项、礼簿、日期、方向，清空亲友、金额、礼品和备注，然后再次自动弹出 PersonPicker。
- 金额为 0 且没有填写礼品时，"保存"键置灰。点击置灰的按键时，弹出提示"金额和礼品至少填一项"。
- 修改礼簿时，如果名目没有被用户手动改过，就跟随新礼簿的类别重新推断。名目一旦被手动修改过，就不再自动变化。
- 保存成功后，把礼簿和事项写入 `last_book_id`、`last_event_id`。

回礼模式的差异：

- 标题为"回礼给 张三"；方向固定为送礼，不显示分段控件；亲友固定。
- 金额区的上方显示被还的记录摘要卡："还 2 笔 · 小明升学宴 · ¥600 ›"，点击可以展开明细。
- 金额默认等于所选记录的合计，可以修改。
- 事项字段的提示文字是"他家的哪个事项？"，因为回礼通常发生在对方办事的时候。
- 状态字段换成一个开关"同时标记为已回礼"，默认打开。关闭时显示提示："部分回礼时可关闭，原记录保持未回礼"。

编辑模式：标题为"编辑记录"；方向和亲友在存在回礼关联时置灰，点击时提示"已关联回礼，先解除关联再修改"；页面底部多一个"删除这笔记录"的文字按钮，`--c-danger` 色。

### 连续录入

为"把纸质礼簿一页页抄进来"这个场景专门设计，追求最快的速度。

```text
┌─────────────────────────────┐
│ ‹        连续录入         完成  │
│ ┌─────────────────────────┐ │
│ │ [学] 小明升学宴 · 收礼      │ │  锁定的上下文卡，fill 底
│ │ 2024 人情礼簿 · 现金 · 8月16日  修改 │ │
│ └─────────────────────────┘ │
│ 第 [1-10] 页  第 3 行   本页 ¥580 / 1,070 │  页码条：页码可编辑，行号自动递增
│ ┌──────────────┬──────────┐ │
│ │ 姓名  张三     │ 金额 500  │ │  两个输入框并排，高 52，大字号
│ └──────────────┴──────────┘ │
│ ┌─────────────────────────┐ │
│ │ 纸本标注（选填）11年国庆 孙女…  │ │  第三个输入框，宋体，可在设置里关闭
│ └─────────────────────────┘ │
│ 联想：[张三 亲戚] [张三丰 朋友]  │  输入姓名时出现的候选 chip
│ [          记 下          ]  │  主按钮，或者在金额框回车
│ 本次已录 23 笔 · 合计 ¥12,600  │  sub ink-2
│ ─────────────────────────── │
│ 张三          ¥500  撤销       │  已录列表，最新的在最上面
│ 李四          ¥200            │  只有最新一行显示"撤销"
└─────────────────────────────┘
```

- 进入连续录入的入口：首页"连续录入"按钮（先选礼簿和事项），或者本子详情的"连续录入"按钮（礼簿已确定，只需选事项）。
- 上下文卡点击"修改"后弹出一个小弹层，可以修改事项、方向、名目、日期。修改后，后续录入的记录使用新的上下文。
- 姓名输入框：输入时在下方显示同名或拼音匹配的候选 chip。回车或者点击金额框时，处理规则如下：恰好有一个完全同名的人，直接使用；没有同名的人，保存时自动新建；有多个同名的人，必须点选其中一个 chip。
- 键盘流（H5）：姓名框回车跳到金额框；金额框回车提交；提交后焦点自动回到姓名框。小程序中，金额框使用数字键盘，"完成"键即提交。
- 支持礼品：在金额框中直接输入文字，例如"被面"，系统识别为礼品名称。金额框的提示文字为"金额或礼品"。
- 遇到重复录入的软确认时，不弹出底部弹层，而是在输入区上方显示一条琥珀色确认条："张三 在本事项本礼簿已有 ¥500，仍要记录？ [取消] [仍然记录]"，键盘焦点停在"仍然记录"上，回车即确认。保证双手不离开键盘就能处理完。
- 撤销：只对最新的一笔有效，直接调用删除接口，不需要再确认。
- 页码条：进入页面时可以填页码和本页合计（纸本页脚上的数字），也可以不填。填了页码后，每笔记录自动带上页码和行号，行号从 1 开始递增。右侧显示"本页已录合计 / 纸本合计"：两者相等时变成绿色并显示对勾；已录合计超过纸本合计时变成琥珀色。点击"下一页"时，页码加一、行号归一、本页合计清空。
- 纸本标注：照抄这一行旁边的手写标注。这里只保存原文，不当场解析成回礼，避免打断抄录节奏。抄完后统一在"整理纸本标注"页处理。键盘流中，金额框回车会跳到标注框，标注框回车提交；标注框为空时，金额框回车直接提交。
- 离开页面时，如果本次录入了带标注的记录，提示"有 6 条标注待整理"，并提供"去整理"按钮。
- 已录列表只保存在本页内存中；离开页面时提示"已录 23 笔，均已保存"。


### 图片识别（仅 H5）

一次只处理一张照片：上传一张、识别一张、人工核对修正、写入，然后进入下一张。不支持多张批量上传，原因是照片可能拍得不全或不清楚，每张都要有人对着纸本核对一遍。识别结果只是草稿，没有经过核对页就不会写入任何数据。

分四步，顶部步骤条：上传 → 识别 → 核对 → 完成。

第一步，上传：

```text
┌─────────────────────────────┐
│ ┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐ │
│      [印章：簿]                 │  虚线框，高 220，可以拖放文件
│    拍照或选择礼簿照片            │
│    支持 jpg / png，不超过 5MB    │
│ └ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘ │
│ 这页礼簿属于                     │
│ 礼簿  (2024 人情礼簿) ›          │  选填，填了之后作为所有识别项的默认值
│ 事项  (小明升学宴) ›              │
│ 方向  [收礼 | 送礼]              │
├─────────────────────────────┤
│ [          开始识别          ]  │
└─────────────────────────────┘
```

- 选择图片后，虚线框变成图片预览，右上角有"旋转""重选""移除"三个按钮。纸本照片常常是横拍的，旋转在前端用 canvas 完成，上传旋转后的图片。
- 第一步还可以填写页码和本页合计，填了的话，会覆盖识别结果中的页码和合计。
- 格式或大小不符合要求时，在虚线框下方显示红字说明，不发起上传。
- 用 `<input type="file" accept="image/*" capture="environment">` 实现，手机浏览器上可以直接调用相机。这段代码只在 `#ifdef H5` 中。

第二步，识别中：

- 图片缩小显示在中间，上面有一条朱砂色半透明扫描线，从上到下循环移动，周期 1.6 秒。
- 下方文字依次变化："正在识别…" → 5 秒后"字迹较多，再等一下…" → 20 秒后"快好了…"。
- 提供"取消"按钮：停止轮询，并回到第一步。
- 失败或超时时：显示错误态，说明原因，提供"重试"和"改为手动录入"两个按钮。手动录入会进入连续录入页，并带上第一步选好的上下文。这一条满足 `fen.md` 4.7 节第 7 条的"不阻塞主流程"。

第三步，核对（最重要的一步）：

```text
┌─────────────────────────────┐
│ [原图缩略图，点击放大]  识别出 18 条 │  缩略图吸顶，高 72
│ [☑ 全选]  批量：方向 ▾ 礼簿 ▾ 名目 ▾ │

│ │  金额 [500  ] 名目 [现金 ▾]   │ │  琥珀点"多个同名，请选择"

│ └─────────────────────────┘ │

│ └─────────────────────────┘ │

│ [ 写入 17 条 · ¥8,600 ]        │  按钮上的数字随勾选实时变化

```

- 每行可以编辑姓名、金额、名目、方向、日期、纸本标注。礼簿和事项默认使用第一步的选择，每行也可以单独覆盖，单独覆盖的行显示"已单独设置"小标。
- 照片拍得不全或有漏识别时，在列表末尾点击"＋ 添加一行"手动补录，也可以在任意行的菜单中"在下方插入一行"，行号自动顺延。识别错误的行可以删除。
- 必须人工确认的行：置信度低于 0.7、大写和阿拉伯数字金额不一致、姓名有多个同名。这些行左侧显示琥珀色"待确认"标记，用户修改或点击"确认无误"后，标记消失。还有待确认的行时，写入按钮不可点击，按钮上方显示"还有 2 行待确认 ›"，点击后滚动到第一个待确认的行。
- 金额不一致的行，在金额框下方显示两个读数："大写 伍拾元 · 小写 30"，点击其中一个即采用。
- 标注写在两行交界处时（识别结果的位置落在两行之间），这一行标为待确认，子行显示"这条标注写在第 9、10 行之间"，提供"属于第 9 行"和"改挂到第 10 行"两个按钮。任何一行的标注也都可以从菜单中改挂到相邻行。
- 有纸本标注的行，在行下方展开一个回礼子行；标注含多次回礼时，展开多个子行，编号 ①②：显示标注原文和解析结果"→ 2011年10月 · 孙女 · 现金 100 + 火炮 20"，以及一个"一并补录回礼"开关，默认打开。点击解析结果，打开 PaperRepaySheet 修改。
- 本页核对条，吸顶在列表上方："本页合计 ¥1,070 · 已选合计 ¥1,070 ✓"。不一致时显示琥珀色，并给出可能的原因："差 ¥50，可能漏识别了一行，或有金额识别错误"。
- "多个同名"的行，点击状态标记后弹出候选人列表，选择其中一个。这种行在用户选择之前不能写入，会被自动取消勾选，并在写入按钮上方提示"1 条需要选择亲友"。
- 后端标记为疑似重复的行，显示琥珀色"可能重复"标记，默认取消勾选，用户可以手动勾选。
- 点击缩略图后，全屏查看原图，支持双指缩放，H5 桌面端支持滚轮缩放。
- 宽屏（不低于 1024）时改为双栏布局：左侧是可缩放、旋转的原图，固定不滚动；右侧是紧凑核对表格，支持键盘操作。完整规格见 `08-Web端能力与宽屏布局.md`。
- 写入失败时（有字段校验错误），根据返回的 `itemErrors` 把对应行和字段标红，并滚动到第一个出错的行。

### 请求层

`api/http.ts` 封装 `uni.request`，骨架中已实现，要点如下：

- 传输层恒为 HTTP 200，`code` 不等于 200 时抛出 `ApiError(code, msg, data, custom)`；网络失败时 code 为 -1。
- H5 的 baseURL 为 `/api/v1`，走 Vite 代理；小程序直连 `VITE_MP_API_BASE`，默认 `http://127.0.0.1:8080/api/v1`。两者用条件编译区分，并通过请求头 `X-Client-Platform` 告诉后端当前端。
- 对外提供 `http.get/post/put/delete`，资源 id 放在 query 中；`unwrapItem`、`unwrapPage` 负责拆包。

- 页面里不直接调用 `http`，只调用 `api/*.ts` 中按领域封装好的函数，例如 `createRecord(params)`。
- 除需要确认之外的错误，由 `request` 调用方的统一 `catch` 处理并弹出提示；页面只处理自己关心的 code，例如 400 用来把表单字段标红。

### 状态管理

Pinia 只存放这些跨页面共享的信息：

- 字典（礼簿类别、名目）：启动时加载一次，修改字典后刷新。
- 设置项与记账上下文：`lastBookId`、`lastEventId`、`quickAmounts`、`showOwing`。从后端加载，修改时写回后端，保证两端一致。

列表和详情数据不放进 store，由页面自己请求，避免出现数据过期的问题。

### 平台判断

`utils/platform.ts` 提供 `isH5`。但是功能边界必须用条件编译实现，不能用运行时判断，这样小程序的产物里才不会包含识别相关代码：

```vue
<!-- #ifdef H5 -->
<GridEntry icon="scan" text="识别礼簿" @click="go('/sub-recognize/index')" />
<!-- #endif -->
```
